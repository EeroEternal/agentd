# AgentOS 变更管理设计

## 目标

增强 Agent 修改文件和服务定义时的可逆性与迭代效率：文件可以从备份恢复，服务定义更新不必重启整个系统。

## 文件恢复

新增 `file.restore`：

- 根据原路径自动选择最近备份，也允许显式指定备份；
- 显式备份必须位于 `/var/lib/agentd/backups/`，防止读取任意文件；
- 恢复前再次备份当前文件；
- 使用原子替换写回；
- 返回恢复来源、当前文件的新备份和内容哈希。

现有 `file.write` 和 `file.delete` 的备份行为保持不变。

## 服务定义热更新

`native.install` 在定义已存在时更新内存中的定义，同时保留当前进程、重启次数和停止状态。运行中的进程不自动重启，只有显式 `native.restart` 或后续异常恢复才使用新定义。

返回值增加 `restart_required`，用于提示运行中的进程与新定义不一致。这样 Agent 可以先修改定义，再决定何时重启，而不是必须重启整个操作系统。

## 验证

1. 写入两个文件版本，恢复最近备份，确认内容回到第一版。
2. 安装一个 ready=true 的测试服务，改为 ready=false 后不重启系统直接 restart，确认新定义生效并出现就绪超时。
3. 验证 heartbeat、网络、SSH 和现有工作流保持正常。
