# AgentOS 实体机内核实验设计

## 目标与范围

在 Omarchy 实体机上建立第一条完整内核实验链路：由 Mac 上的 Agent 通过 SSH 驱动，构建与当前系统匹配的 Linux 内核，生成独立 initramfs 和 Limine 启动项，保留原始 Omarchy 启动路径，并由用户从启动菜单手动选择测试内核。

首个里程碑使用不带功能修改的基线内核，验证源码、配置、构建、安装和实体机启动。基线启动成功后，再单独设计第一个 Agent 生成补丁。

本阶段不包括 QEMU、自动启动回退、自定义调度器、替换 PID 1、Agent-native 内核或模型推理运行时迁移。

## 已确认环境

- Lenovo ThinkPad X240，Intel i5-4210U，4 个逻辑 CPU，约 8 GB 内存。
- Omarchy，x86_64，当前内核为 `7.1.9-arch1-2`。
- 传统 BIOS 启动，Limine 12.6.0；不是 GRUB。
- LUKS 加密根卷，Btrfs 根文件系统，Snapper 已配置并存在快照。
- 根文件系统剩余约 91 GB 空间。
- 当前没有 `/dev/kvm`，不依赖硬件虚拟化。
- 当前缺少部分内核构建依赖。
- SSH 使用 `admin@192.168.3.11`，管理员具有 sudo 权限。

## 方案选择

采用实体机完整内核闭环。相比仅构建模块，它能验证完整的内核替换路径；相比 QEMU，它符合直接操作实体机的目标，也避免该机器缺少 KVM 导致的慢速模拟。

原始内核和默认 `Omarchy` 启动项保持不变。测试内核只增加独立的 `AgentOS Test` 启动项，首轮由用户手动选择，不假定 Limine 具备尚未验证的一次性启动或自动回退能力。

## 组件与职责

### Mac 上的 Agent

负责分析任务、生成操作、通过 SSH 调用执行器、读取日志和判断测试结果。不在这台 X240 上运行大模型。

### Omarchy 上的 agentd

一个以 root 运行的本地执行服务，仅通过 root 所有的 Unix Socket 接收请求，不新增 TCP 监听。首版支持：

- 执行系统命令并返回退出状态、标准输出和标准错误；
- 创建和管理独立构建任务；
- 获取内核源码与运行配置；
- 构建内核和模块；
- 生成 initramfs；
- 安装测试启动产物；
- 保存每个任务的日志和元数据。

执行器可以运行任意系统命令，这是实验目标的一部分。项目文件和日志不得保存 SSH、sudo 或 root 凭据。

### 工作目录

使用 `/srv/agentos`：

- `src/`：固定版本的内核源码；
- `build/`：独立构建目录；
- `artifacts/`：通过构建的内核、模块和配置；
- `runs/`：每次任务的日志、状态和构建元数据；
- `agentd/`：执行器实现与配置。

每次构建使用独立任务目录，避免覆盖其他任务。原始系统文件不属于该工作目录。

## 构建与安装流程

1. 创建新的 Snapper 快照，记录当前 Limine 配置和启动产物状态。
2. 安装缺失的内核构建依赖，不删除现有软件包。
3. 获取与当前 `7.1.9-arch1-2` 匹配的 Arch 内核源码及补丁，不以未验证的原版 Linux 标签替代。优先使用运行内核导出的配置；不可用时使用该 Arch 内核版本对应的构建配置。
4. 设置独立的内核发布标识 `7.1.9-agent1`，避免与发行版模块目录冲突。
5. 使用独立构建目录，以 `-j2` 为初始并行度构建内核和模块。
6. 构建成功后安装到独立暂存区，验证内核镜像、模块目录和版本标识。
7. 使用现有 mkinitcpio preset、主配置及全部 drop-in 配置为测试内核生成独立 initramfs，并确认实际 hooks 支持当前 `cryptdevice` 启动参数、LUKS、Btrfs 和键盘，而不只复制主配置文件。
8. 将测试产物安装到 `/boot` 下独立的 AgentOS 目录，不覆盖当前 `vmlinuz` 或 `initramfs`。
9. 为 Limine 添加 `AgentOS Test` 项，沿用已验证的 LUKS、根卷和 Btrfs 参数，并移除不必要的静默参数以便诊断。默认启动项不变。
10. 重新读取配置和产物，核对路径、版本及原始启动项，再交给用户手动重启测试。

只有前一步成功才继续下一步。编译或 initramfs 失败时不得修改 Limine 配置。

## 错误处理与恢复

- 构建失败：保留完整日志和任务目录，原始系统启动配置不变。
- 安装失败：使用暂存区，不在原位置覆盖；清理不完整的测试产物后再重试。
- Limine 配置异常：恢复修改前备份，确认原始 `Omarchy` 项仍可解析。
- 测试内核无法启动：用户重启并选择原始 `Omarchy` 项；LUKS 解锁仍按现有流程进行。
- 测试系统启动但 SSH 不可用：收集本地控制台信息后返回原系统，不把网络可用误判为内核整体可用。
- agentd 失败：不影响现有 SSH 和 systemd，可通过 sudo 修复或停止服务。

本阶段不承诺无人值守恢复。用户需要能够在实体机启动菜单选择原始系统。

## 验证

### 构建前

- 依赖和磁盘空间满足构建要求。
- 当前默认启动项、内核文件和 Snapper 快照已记录。
- agentd 能执行命令并正确返回输出、错误和退出状态。
- 普通命令与失败命令均有对应日志。

### 构建后

- `bzImage`、模块和 initramfs 均存在且属于 `7.1.9-agent1`。
- 模块安装目录与内核发布标识完全一致。
- Limine 中同时存在原始 `Omarchy` 和新增 `AgentOS Test` 项。
- 原始启动产物未被替换，默认启动项未改变。

### 实体机启动后

- `uname -r` 显示 `7.1.9-agent1`。
- 根卷正常解锁并以读写方式挂载预期 Btrfs 子卷。
- systemd 正常运行，没有进入 emergency target。
- 网络与 SSH 可用，Mac 能重新连接。
- 关键硬件驱动正常加载，至少覆盖存储、有线或无线网络及显示。
- agentd 和原始 Omarchy 系统服务可管理。
- 重启回原始内核后，`uname -r` 恢复为 `7.1.9-arch1-2`。

只有上述实体机验证通过，首个里程碑才算完成。

## 后续独立里程碑

基线内核可启动后，再选择一个小型、可观测的内核修改作为 Agent 生成任务，例如增加只读状态接口或启动标记。该修改需要新的任务、补丁、日志和实体机验证，不与基线构建混合。
